# 📜 Правила Розробки Проєкту Smart-BKT-Chain (Workspace Agent Rules)

Цей файл визначає обов'язкові інструкції та регламент роботи для AI-асистента в межах цього проєкту.

---

### 1. 📝 Обов'язковий порядок оновлення документації (Mandatory Progress Logging)
Після виконання **кожного мікро-кроку або етапу** розробки асистент **ЗОБОВ'ЯЗАНИЙ** без додаткового нагадування виконувати такі 3 дії:

1. **Оновлення Денного Прогресу:**
   - Додавати короткий підсумок виконаних задач у файл [`docs/daily_progress.md`](file:///d:/PROJECTS/MAGISTERS/SMART-BKT-CHAIN/docs/daily_progress.md).

2. **Оновлення Детального Технічного Журналу:**
   - Додавати детальний технічний опис (архітектура, схеми БД, математичні формули BKT, назви файлів, REST/WS ендпоінти) у файл [`docs/detailed_implementation_log.md`](file:///d:/PROJECTS/MAGISTERS/SMART-BKT-CHAIN/docs/detailed_implementation_log.md).

3. **Компіляція JSON для порталу документації:**
   - Запускати команду `python scripts/compile_docs.py`, щоб оновити всі JSON-дані у папці `apps/docs/src/data/` для веб-сайту `apps/docs`.

---

### 2. 🧩 Покрокова розробка невеликими ітераціями (Micro-Step Execution)
- Всі задачі розбиваються на прозорі **мікро-кроки** (Micro-Steps).
- Після кожного мікро-кроку проводиться перевірка збірки (`npm run build:*`) або unit-тестів (`npm run test:*`).
- Кожен завершений мікро-крок фіксується окремим `git commit`.

---

### 3. 🔍 Сувора перевірка логів та захист від припущень
- Ніколи не робити припущень щодо помилок збірки без читання повного логу помилок.
- Завжди перевіряти авторитетні джерела коду перед виправленням імпортів або типів.
