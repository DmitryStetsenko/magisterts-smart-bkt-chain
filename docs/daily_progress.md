6. **Phase 2 · Крок 6: Мультирежимне Відображення Дерева Аномалій (Module Tree DAG, Category Tree, DAG Graph, RPG Matrix):**
   - **Режими відображення (`viewMode`):**
     1. **`module_tree` (Дерево Модулів за DAG-ієрархією — За замовчуванням):**
        - Ієрархія будується безпосередньо за топологією модулів курсу: кореневі модулі, у яких сталися аномалії $\to$ вкладені дочірні модулі DAG-ланцюга.
        - Якщо декілька модулів з аномаліями належать до одного рівня ієрархії або мають спільного предка — вони групуються як сусіди поруч.
        - **Миттєва видимість інформації про завдання:** Всередині кожного модуля кожна картка запитання містить чітку назву завдання, тип (`SINGLE_CHOICE`, `CODE`), прев'ю змісту питання/опису завдання, бейджі телеметрії (`G=0.85`, `S>0.2`), часові мітки та вердикт рушія BKT.
     2. **`tree` (Ієрархічне Дерево за категоріями):** Згортання/розгортання за категоріями аномалій із такими ж розширеними картками питань.
     3. **`graph` (Топологічний граф знань):** Інтерактивна топологічна сітка модулів курсу із відображенням статусу засвоєння $P(L)$, бейджами кількості когнітивних аномалій (`⚡ Вгадування`, `⚠️ Описки`) та інтерактивною правою панеллю інспектора для аудиту всіх інцидентів конкретного вузла.
     4. **`rpg` (Кібер-рунічна матриця навичок):** Гейміфікована сітка навичок із рунічними кристалами, неоновим світінням статусів (`Засвоєно ✨`, `В процесі ⚡`, `Заблоковано 🔒`) та виділенням аномальних вузлів.
   - **Автоматичне збагачення метаданих завдань:** При відсутності прямого кешу в історії BKT клієнт автоматично збагачує запис назвою, повним описом та варіантами відповідей із завантажених завдань відповідного модуля курсу, гарантуючи, що модальне вікно та дерево завжди містять реальний текст та варіанти відповідей.
   - **Оптимізація анімацій на деревах навичок:** Анімація підстрибування іконок (`animate-bounce`) обмежена виключно вибраним (`isSelected`) або поточним активним (`isCurrentActive`) вузлом замість усіх засвоєних/аномальних модулів одночасно.
   - **Модульність та універсальність:** Віджет виконаний автономним модулем, який приймає `adjustments` та `nodes`, і може бути легко вбудований як у кабінет викладача (`apps/teacher`), так і у студентський кабінет (`apps/student`) для цілей відладки.
   - **Перевірка надійності:** Всі 19/19 юніт-тестів API пройшли успішно, збірка `build:teacher` пройшла без зауважень.
