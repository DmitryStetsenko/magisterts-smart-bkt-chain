# 📐 Стандарт та Методологічний Регламент Створення Завдань (Task Authoring & Pedagogical Specification Standard)

**Дата затвердження:** 20 жовтня 2026 р.  
**Проєкт:** Smart-BKT-Chain (Адаптивна освітня Web3-платформа)  
**Цільове призначення:** Регламент для викладачів, методистів, контент-мейкерів та AI-агентів генерації завдань для забезпечення безшовної роботи моделі адаптивного навчання (BKT + IRT + Bloom's Taxonomy).

---

## 📌 1. Фундаментальні Принципи Проєктування Завдань

У системі **Smart-BKT-Chain** завдання не є розрізненим набором тестових питань. Кожне завдання — це вимірювальний калібр знань (Knowledge Component Probe), інтегрований у:
1. **Граф компетенцій (DAG):** прив'язка до макро-модуля `SkillNode` (`skillId`).
2. **Таксономію Блума:** відповідність когнітивному рівню (Remember, Understand, Apply, Analyze, Evaluate, Create).
3. **Діагностичну матрицю:** прив'язка до мікро-теми (`topic`) та конкретного під-концепту (`subConcept`).
4. **Спадну адаптивність (Top-Down Challenge & Graceful Degradation):** завдання має органічно входити в «тріаду складності» теми.

---

## 🔺 2. «Тріада Складності» Кожної Мікро-Теми (Cognitive Triad)

Будь-яка навчальна мікро-тема (`topic`), що додається до курсу, **ЗОБОВ'ЯЗАНА** мати повний комплект із трьох рівнів складності. Неприпустимо створювати тему, яка містить лише одну складність.

```
                  ▲
                 / \
                /   \     🔴 HARD (Синтез, Архітектура, Edge Cases)
               / HARD\    → Monaco Code Editor, повна реалізація, 100% Max Score
              /───────\
             /         \   🟡 MEDIUM (Аналіз, Bug Hunt, Декомпозиція)
            /  MEDIUM   \  → Написання частини коду, пошук багів, концептуальний аналіз
           /─────────────\
          /               \ 🟢 EASY (Розпізнавання, Синтаксис, Правила)
         /      EASY       \→ Single/Multi Choice, допоміжний рівень (Max 70% Score)
        /───────────────────\
```

### 2.1. 🟢 Рівень `EASY` (Базовий / Scaffolding & Remediation)
- **Мета:** Закріплення фундаментальних правил, зняття когнітивного блоку після помилки, діагностика первинного сприйняття.
- **Типові формати:** `SINGLE_CHOICE`, `MULTIPLE_CHOICE`, найпростіший `CODE` (1–2 рядки).
- **Когнітивний рівень Блума:** *Remember* (Згадування) & *Understand* (Розуміння).
- **Характеристики:**
  - Однозначне питання без заплутаних подвійних заперечень.
  - 3–4 дистрактори (варіанти), з яких хибні варіанти представляють типові студентські помилки, а не абсурдні тексти.
  - Призначення системи: **допоміжний рівень** (Graceful Degradation), активується при помилці на складніших завданнях, встановлює кеп підсумкового балу на рівні 70%.

### 2.2. 🟡 Рівень `MEDIUM` (Стандартний / Core Application)
- **Мета:** Перевірка вміння застосовувати концепт на практиці, аналізувати готовий код або будувати класичні алгоритми.
- **Типові формати:** `CODE` (Monaco Editor), `TEXT_ESSAY` (пояснення концепції), поглиблений `SINGLE_CHOICE`.
- **Когнітивний рівень Блума:** *Apply* (Застосування) & *Analyze* (Аналіз).
- **Характеристики:**
  - Базові алгоритми, робота зі структурами даних середньої складності.
  - Завдання типу **«Bug Hunt»**: надано робочий фрагмент із логічною або синтаксичною вадою, яку потрібно виявити та виправити.
  - Початкова точка для більшості студентів при вході в тему (100% максимальний бал).

### 2.3. 🔴 Рівень `HARD` (Просунутий / Synthesis & Mastery Challenge)
- **Мета:** Перевірка стійкості знань на граничних умовах (edge cases), рекурсії, оптимізації та композиції кількох під-концептів.
- **Типові формати:** `CODE` з прихованими складними тест-кейсами (`isSecret: true`), розгорнутий `TEXT_ESSAY` з оцінкою контр-аргументів.
- **Когнітивний рівень Блума:** *Evaluate* (Оцінка) & *Create* (Створення).
- **Характеристики:**
  - Робота з нетривіальними типами даних, порожніми значеннями (`null`, `undefined`, `NaN`, `[]`, `""`).
  - Вимога до чинності алгоритму (наприклад, $O(n)$ замість $O(n^2)$ або чисті функції без сайд-ефектів).
  - Успішне розв'язання дає максимальний приріст до BKT $P(L)$ та прямий шлях до Gold Mastery Badge ($\ge 0.90$).

## 🏷️ 3. Таксономія Іменування `topic` та `subConcept`

Поля `topic` та `subConcept` є машинно-читабельними ключами діагностики для бекенд-секвенсера (`TaskSequencer`) та мікро-агентів генерації завдань.

### 3.1. Правила форматування:
- Використовувати тільки **`kebab-case`** у латиниці (наприклад: `variables-declaration`, `event-loop`).
- `topic`: визначає макро-тему в межах модуля (3–6 тем на модуль).
- `subConcept`: визначає атомарний механізм чи підводний камінь (1–4 під-концепти на тему).

### 3.2. Приклади зв'язки для курсу JavaScript:

| Модуль (`SkillNode.slug`) | Мікро-тема (`topic`) | Під-концепт (`subConcept`) | Приклад завдання |
| :--- | :--- | :--- | :--- |
| `js-basics` | `variables-declaration` | `const-immutability` | Поведінка `const` з примітивами та об'єктами |
| `js-basics` | `variables-declaration` | `temporal-dead-zone` | Доступ до `let` до ініціалізації (TDZ) |
| `js-basics` | `primitive-types` | `type-coercion` | Результат виразів `"5" - 2` та `"5" + 2` |
| `js-basics` | `primitive-types` | `strict-equality` | Порівняння `NaN === NaN`, `Object.is` |
| `js-basics` | `arithmetic-and-loops`| `parity-check` | Перевірка парності цілих та від'ємних чисел |
| `js-basics` | `arithmetic-and-loops`| `prime-number-check` | Алгоритм визначення простого числа |
| `js-functions` | `arrow-functions` | `lexical-this` | Втрата контексту `this` у callback |
| `js-functions` | `closures` | `counter-closure` | Збереження приватного стану лічильника |
| `js-functions` | `closures` | `currying-memo` | Каррування функцій `f(a)(b)` |
| `js-collections`| `array-methods` | `map-vs-foreach` | Чистота методів, що повертає `forEach` |
| `js-collections`| `array-methods` | `reduce-aggregation` | Агрегація масиву у складний об'єкт |
| `js-async` | `event-loop` | `micro-vs-macro` | Пріоритет виконання `Promise` vs `setTimeout` |
| `js-async` | `async-await` | `error-handling` | Перехоплення помилок через `try...catch` |
| `js-oop` | `classes-es6` | `extends-super` | Наслідування та виклик `super()` у конструкторі |

## 💻 4. Специфікація Форматів Завдань та Схем Даних

### 4.1. Практичне Завдання на Код (`TaskType.CODE`)

```typescript
{
  skillId: "uuid-вузла",
  topic: "arithmetic-and-loops",
  subConcept: "clamping-algorithm",
  taskType: "CODE",
  difficulty: "MEDIUM", // EASY | MEDIUM | HARD
  title: "Обмеження діапазону (Clamp Number)",
  description: "Напишіть функцію `clamp(num, min, max)`, яка обмежує число `num` в діапазоні між `min` та `max`.",
  starterCode: "function clamp(num, min, max) {\n  // Ваш код тут\n}",
  testCases: {
    create: [
      // Відкриті тест-кейси (студент бачить їх у панелі)
      { input: "[5, 0, 10]", expectedOutput: "5", isSecret: false },
      { input: "[-5, 0, 10]", expectedOutput: "0", isSecret: false },
      // Приховані стрес-тести (запобігають хардкоду відповідей)
      { input: "[15, 0, 10]", expectedOutput: "10", isSecret: true },
      { input: "[0, 0, 0]", expectedOutput: "0", isSecret: true }
    ]
  }
}
```

#### Вимоги до тест-кейсів коду:
1. `input` **ЗАВЖДИ** є валідним JSON-масивом параметрів функції (наприклад: `"[2, 3]"` або `'[["apple", "banana"]]'`).
2. `expectedOutput` є точним рядковим або серіалізованим значенням очікуваного повернення (наприклад: `"5"`, `"true"`, `'{"a":1}'`).
3. Кожна задача повинна мати **мінімум 2 відкритих** (`isSecret: false`) і **1–2 секретних** (`isSecret: true`) тест-кейси для захисту від фальсифікації результатів.

---

### 4.2. Тестові Завдання (`SINGLE_CHOICE` / `MULTIPLE_CHOICE`)

```typescript
{
  skillId: "uuid-вузла",
  topic: "variables-declaration",
  subConcept: "const-immutability",
  taskType: "SINGLE_CHOICE", // або MULTIPLE_CHOICE
  difficulty: "EASY",
  title: "Теорія JS: Оголошення змінних `const`",
  description: "Що відбудеться при спробі повторного присвоєння значення змінній, оголошеній через `const x = 10`?",
  options: [
    { id: "opt1", text: "Значення успішно зміниться", isCorrect: false },
    { id: "opt2", text: "Виникне помилка TypeError: Assignment to constant variable", isCorrect: true },
    { id: "opt3", text: "Змінна стане undefined", isCorrect: false }
  ]
}
```

#### Вимоги до варіантів відповідей:
1. Кожен варіант має унікальний рядковий ідентифікатор (`id: "opt1"`, `"opt2"` тощо).
2. Поле `isCorrect: boolean` чітко визначає правильність:
   - Для `SINGLE_CHOICE`: **рівно один** варіант з `isCorrect: true`.
   - Для `MULTIPLE_CHOICE`: **два або більше** варіантів з `isCorrect: true`.

### 4.3. Розгорнута Відповідь / Есе (`TEXT_ESSAY` / `OPEN_TEXT`)

```typescript
{
  skillId: "uuid-вузла",

  referenceAnswer: "Event Loop контролює Call Stack та черги Microtasks/Macrotasks. Microtasks (Promises) виконуються першочергово після поточного стеку...",
  options: {
    keywords: [
      "microtask|мікротаск|promise|проміс",
      "macrotask|макротаск|settimeout|таймер",
      "call stack|стек",
      "черга|queue"
    ],
    minWords: 15
  },
  rubrics: {
    keywords: [
      "microtask|мікротаск|promise|проміс",
```

#### Вимоги до семантичних есе:
1. Обов'язкове поле `referenceAnswer` — зразок вичерпної та коректної відповіді.
2. Масив `keywords`: регулярні вирази або синонімічні ланцюжки через `|` українською та англійською мовами.
3. Поле `minWords`: мінімальна когнітивна довжина для запобігання однослівним відпискам.

## 📋 5. Чек-Лист Валідності Завдання Перед Додаванням у Базу

Перед збереженням завдання у `seed.ts` або публікацією через Admin CMS перевірити:

- [ ] **Чітка назва та контекст:** Заголовок містить суть задачі, а опис чітко формулює що саме очікується.
- [ ] **Присутність `topic` та `subConcept`:** Заповнені у форматі `kebab-case`.
- [ ] **Відповідність складності:** `EASY` не вимагає написання складного коду, `HARD` містить нетривіальні тест-кейси.
- [ ] **Валідність синтаксису коду:** Заготовка `starterCode` компілюється без синтаксичних помилок і має правильні сигнатури параметрів.
- [ ] **Коректність тест-кейсів:** Усі `input` та `expectedOutput` відповідають очікуваному типажу JS (числа як рядки чисел, масиви як JSON-рядки).
- [ ] **Відсутність суб'єктивності в тестах:** У `SINGLE_CHOICE` є тільки одна беззаперечно правильна відповідь.
- [ ] **Наявність симетричних завдань:** У цієї ж теми є завдання інших рівнів складності для забезпечення адаптивного переходу.
