# 🧠 Сесія 20: Продакшен-Архітектура Створення Курсів: Наскрізна Інтеграція, ШІ-Скеффолдинг, Табличний Імпорт/Експорт (Excel/Google Sheets) та Версіонування

Цей документ фіксує результати 20-ї сесії архітектурного брейншторму платформи **Smart-BKT-Chain**, присвяченої фундаментальному перетворенню процесу створення та налаштування навчальних курсів із локальної форми в повноцінну виробничу (Production-Ready) підсистему курсового інжинірингу.

## 🎯 1. Контекст, Проблематика та Візія Продакшену

Створення адаптивного курсу в системі Smart-BKT-Chain суттєво відрізняється від звичайних LMS (Moodle, Canvas, Google Classroom), оскільки курс у нашій платформі є **динамічним математично-дидактичним графом знань**, де кожен елемент безпосередньо впливає на роботу 5 ключових підсистем екосистеми:

```
                                  ┌─────────────────────────────┐
                                  │      КУРС НАВЧАННЯ          │
                                  │   (Курсовий Граф Знань)     │
                                  └──────────────┬──────────────┘
                                                 │
         ┌───────────────────┬───────────────────┼───────────────────┬───────────────────┐
         ▼                   ▼                   ▼                   ▼                   ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│   apps/admin    │ │   apps/study    │ │  apps/student   │ │  apps/teacher   │ │    apps/api     │
│   (CMS & DAG)   │ │  (Zen Focus v2) │ │ (Monaco & BKT)  │ │ (Класи & Зрізи) │ │ (BKT Sequencer) │
│ Керування курсом│ │ Читалка уроків, │ │ Адаптивний шлях,│ │ Призначення тем,│ │ Обчислення P(L),│
│ пороги майстер- │ │ код-пісочниці,  │ │ телеметрія WPM, │ │ когортний аналіз│ │ перевірка тестів│
│ ності, перевірка│ │ картки оман     │ │ mastery-гейтинг │ │ черга рецензій  │ │ блокчейн-аудит  │
└─────────────────┘ └─────────────────┘ └─────────────────┘ └─────────────────┘ └─────────────────┘
```

### Чому поточне рішення потребує фундаментальної модернізації?
1. **Ручна трудомісткість (Manual Fatigue):** Створення якісного STEM-курсу на 5 модулів, 20 компетенцій та 80 адаптивних завдань у ручному режимі займає у викладача/методиста **від 40 до 80 годин монотонної праці**.
2. **Бар'єр входу для викладачів:** Більшість освітян не є інженерами знань. Вони мають напрацьовані матеріали у Google Таблицях, Excel, конспектах Word або PDF-програмах МОН, але не можуть перенести їх в 1 клік.
3. **Холодний старт BKT:** Ручне калібрування байєсівських апріорних ймовірностей $P(L_0), P(T), P(S), P(G)$ лякає користувачів математичною складністю.
4. **Ризик деструкції активних сесій:** Якщо викладач змінює структуру опублікованого курсу (видаляє компетенцію чи міняє слаг модуля), активні сесії студентів і ланцюжки доказів у блокчейні можуть пошкодитися.
5. **Відсутність валідатора повноти (Pre-Flight Linter):** Курс можна опублікувати з порожніми модулями, компетенціями без завдань або циклами в графі пререквізитів ($A \to B \to A$).

## 🧭 2. Покроковий Аудит Поточного Стану (As-Is Architecture)

На даний момент у платформі реалізовано 5-кроковий майстер створення курсу у `apps/admin`:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                          ПОТОЧНИЙ 5-КРОКОВИЙ МАЙСТЕР АВТОРА КУРСУ                      │
└────────────────────────────────────────────────────────────────────────────────────────┘
 [Крок 1: Метадані] ──► [Крок 2: Модулі] ──► [Крок 3: DAG] ──► [Крок 4: Теорія] ──► [Крок 5: Завдання]
```

### 2.1. Як елементи курсу пов'язані з підсистемами платформи зараз:

| Рівень ієрархії | Сутність у БД | Де створюється / редагується | Де використовується у платформі |
|---|---|---|---|
| **Рівень 1: Курс** | `Course` | `CourseCreateView` / `CourseStudioView` (Крок 1) | `apps/admin` (Каталог), `apps/teacher` (Призначення класу), `apps/student` (Вибір курсу в профілі), `apps/study` (Навігація підручника) |
| **Рівень 2: Модуль** | `CourseModule` | `CourseStudioView` (Крок 2, форма + авто-слаг) | `apps/study` (`/learn/:courseSlug/:moduleSlug`), `apps/student` (Модульний сайдбар з BKT-гейтингом), `apps/teacher` (`allowedModuleIds`) |
| **Рівень 3: Компетенція** | `SkillNode` | `CreateSkillModal` / DAG Canvas (Крок 3) | `apps/api` (Матриця BKT-станів $P(L)$), `apps/student` (Дерево навичок, розрахунок прогресу), `apps/teacher` (Когортне дерево аномалій) |
| **Рівень 4: Конспект** | `CourseModule.description` / `studyUnitUrl` | `TheoryLessonBuilderView` (Крок 4) | `apps/study` (Zen Focus Reading Engine: 5 дидактичних блоків уроку, когнітивні омани, перехід у практику) |
| **Рівень 5: Завдання** | `Task` (`CODE`, `MULTIPLE_CHOICE`, `ESSAY`) | `CreateTaskModal` (Крок 5) | `apps/student` (Monaco Editor, перевірка тестів Jest/PyTest, збір телеметрії WPM/пауз), `apps/api` (BKT Inference Engine) |

## 🔍 3. Системний Аналіз Вузьких Місць (Bottlenecks & Gaps)

Нижче наведено вичерпний реєстр інженерних та дидактичних бар'єрів, які відокремлюють поточний стан від повноцінного комерційного продакшену:

```
                 ВУЗЬКІ МІСЦЯ ПОТОЧНОЇ СИСТЕМИ СТВОРЕННЯ КУРСУ
┌──────────────────────────────────────────────────────────────────────────────────┐
│ 1. Ручна втома: створення 1 уроку займає 45 хв; немає шаблонізації та автогенерації│
│ 2. Відсутність імпорту: немає завантаження із Google Sheets, Excel чи Markdown   │
│ 3. Складність Skill DAG: автор вручну вбиває пререквізити; немає валідатора циклів│
│ 4. Сліпе калібрування BKT: автор «вгадує» pL0, pT, pS, pG без підказок складності  │
│ 5. Відсутність версіонування: зміни ламають активні сесії студентів у БД         │
│ 6. Відсутність Pre-flight чекера: курс можна опублікувати недоробленим           │
│ 7. Ізольованість контенту: неможливо експортувати курс колезі або клонувати      │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### Деталізація вузьких місць:
1. **Неможливість масового імпорту структури (Bulk Ingestion Gap):**
   - Методист приходить із робочою навчальною програмою у таблиці Google Sheets. Зараз йому потрібно клікнути 100+ разів кнопками `[+ Додати модуль]`, `[+ Додати компетенцію]`, `[+ Додати задачу]`.
2. **Відсутність ШІ-генератора структури та наповнення (AI Scaffolding Void):**
   - Сучасні LMS нового покоління повинні дозволяти ввести: *«Створи курс з веб-безпеки для 10 класу за стандартом МОН на 4 модулі»* і за 30 секунд отримати готовий чернетковий каркас із зразками коду, оманами та тестами.
3. **Ризик топологічних помилок у Skill DAG:**
   - Пререквізити задаються через мультиселект. Легко створити циклічну залежність ($A \to B \to C \to A$), через яку секвенсор BKT у `apps/api` зависне у нескінченному циклі або заблокує студенту проходження курсу.
4. **Непрозорість BKT-параметрів для неспеціалістів:**
   - Поля $P(L_0), P(T), P(S), P(G)$ збивають з пантелику гуманітарних авторів. Потрібна автоконфігурація на основі обраної складності завдання (EASY / MEDIUM / HARD) або емпіричний перемикач пресетів.
5. **Мутабельність опублікованих курсів (Zero Versioning):**
   - Якщо курс уже проходять 100 учнів, видалення або перейменування компетенції призводить до виникнення «сирітських» записів у таблиці `student_skill_mastery` та порушує хеш-ланцюг атестації.

## 🤖 4. Концепція та Архітектура ШІ-Інжинірингу Курсів (AI Course Scaffolding Engine)

Щоб зробити створення курсу швидким та інтелектуальним, архітектура повинна підтримувати **дворівневу інтеграцію ШІ**:
1. **Генератор повного курсу «під ключ» за 1 промптом (One-Shot Course Scaffolder)**.
2. **Контекстний ШІ-копілот на кожному з 5 кроків майстра (In-Step AI Assistant)**.

```
                              АРХІТЕКТУРА ШІ-ІНЖИНІРИНГУ КУРСУ
┌───────────────────────────────────────────────────────────────────────────────────────┐
│ Запит автора: "Курс 'Кібергігієна та Захист Даних', 10 клас, 4 модулі, BKT поріг 0.85" │
└───────────────────────────────────┬───────────────────────────────────────────────────┘
                                    │
                                    ▼
┌───────────────────────────────────────────────────────────────────────────────────────┐
│                              LLM Course Architect Engine                               │
│                         (Gemini 2.5 Pro / Flash via apps/api)                         │
├───────────────────────────────────────────────────────────────────────────────────────┤
│ 1. Генерує валідний Course JSON Schema за стандартом @sbc/types                       │
│ 2. Автоматично розбиває теми на модулі та впорядковує чергу orderIndex               │
│ 3. Будує орієнтований ациклічний граф компетенцій (Skill DAG) із транзитивними зв'язками │
│ 4. Калібрує BKT-параметри відповідно до таксономії Блума та складності задач          │
│ 5. Пише 5-блочний дидактичний конспект для кожного модуля з когнітивними оманами     │
│ 6. Формує банк із 3-5 адаптивних завдань на навичку (з тестами Jest/Pytest)          │
└───────────────────────────────────┬───────────────────────────────────────────────────┘
                                    │
                                    ▼
┌───────────────────────────────────────────────────────────────────────────────────────┐
│                         Інтерактивний Інспектор Чернетки                              │
│   Автор бачить розгорнуте дерево курсу ➔ коригує під себе ➔ тисне "Створити Курс"     │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.1. Специфікація ШІ-копілота на кожному з 5 кроків:

#### 🔹 Крок 1: Базові метадані курсу
- **Кнопка в UI:** `[ ✨ Згенерувати анотацію та мету курсу ]`.
- **Вхідні дані:** Назва курсу, категорія та цільова аудиторія.
- **Вихід ШІ:** Повний педагогічний опис, матриця очікуваних результатів навчання (Learning Outcomes) за стандартами МОН та рекомендований BKT-поріг майстерності (0.80, 0.85 чи 0.90) з обґрунтуванням.

#### 🔹 Крок 2: Модульна структура
- **Кнопка в UI:** `[ ✨ Запропонувати модульну структуру курсу ]`.
- **Вхідні дані:** Назва курсу + бажана кількість модулів (наприклад, 4 або 6).
- **Вихід ШІ:** Масив модулів із коректними транслітерованими слагами, лаконічними описами дидактичних цілей та попередньо сформованими посиланнями `theoryUrl`.

#### 🔹 Крок 3: Граф компетенцій (Skill DAG) та авто-калібрування BKT
- **Кнопка в UI:** `[ ✨ Побудувати граф компетенцій та залежностей ]`.
- **Вхідні дані:** Перелік модулів курсу.
- **Вихід ШІ:**
  - 3–6 атомарних навичок для кожного модуля.
  - Матриця пререквізитів без циклів (гарантовано ациклічний граф $G=(V, E)$).
  - Автоматичне призначення складності (EASY $\to$ $P(L_0)=0.6, P(T)=0.15$; HARD $\to$ $P(L_0)=0.2, P(T)=0.05, P(S)=0.15, P(G)=0.10$).

#### 🔹 Крок 4: Конспекти уроків (Zen Focus 5-Block Engine)
- **Кнопка в UI:** `[ ✨ Написати структурований урок за стандартом Zen Focus ]`.
- **Вхідні дані:** Назва модуля та перелік прив'язаних компетенцій.
- **Вихід ШІ:** Повний урок у форматі 5 дидактичних блоків:
  1. *Блок 1 (Вступ):* Практична актуалізація теми (навіщо це в житті).
  2. *Блок 2 (Теорія):* Фундаментальні поняття, лаконічні правила, таблиці.
  3. *Блок 3 (Код/Синтаксис):* Робочі зразки коду для інтерактивної пісочниці.
  4. *Блок 4 (Омани - Misconceptions):* 2–3 типові помилки початківців із поясненням правильного мислення.
  5. *Блок 5 (Шлюз практики):* Перехідний зв'язок до адаптивних задач тренажера.

#### 🔹 Крок 5: Банк завдань та валідаційні тести
- **Кнопка в UI:** `[ ✨ Згенерувати адаптивні завдання з тестами ]`.
- **Вхідні дані:** Компетенція BKT + тип задачі (`CODE` або `MULTIPLE_CHOICE`).
- **Вихід ШІ:**
  - Постановка умови задачі.
  - Стартовий шаблон коду з плейсхолдерами `// ВАШ КОД ТУТ`.
  - Зразок еталонного розв'язку.
  - **Автоматичні тестові кейси (Unit Tests)** із прихованими та відкритими тестами.
  - Сходинки сократівських підказок (Hint Ladder) від натяку до аналізу помилки.

```
               ▼
┌──────────────────────────────┐
│  Модальне Вікно Pre-Flight:  │ ──► Автор бачить підсумок: «Буде імпортовано 3 модулі,
│    Підсумок та Помилки       │     12 компетенцій, 36 задач. 0 критичних помилок»
└──────────────┬───────────────┘
               │ [Тисне "Підтвердити Імпорт"]
               ▼
┌──────────────────────────────┐
│   Атомарна Транзакція БД     │ ──► Prisma $transaction: Створює Course, Modules,
│    (PostgreSQL Transaction)  │     SkillNodes, зв'язки DAG та Tasks за 1 секунду!
└──────────────────────────────┘
```

- **Атомарність імпорту:** Якщо в одному завданні є синтаксична помилка, транзакція відкочується назад (Rollback), і автор бачить конкретний рядок таблиці з помилкою. Курс не створюється «наполовину».
- **Експорт у 1 клік:** Будь-який існуючий курс можна експортувати у готовий `.xlsx` або синхронізувати в Google Sheets для передачі іншим викладачам.

## 🛡️ 6. Продакшен-Архітектура: Що ще необхідно врахувати

Щоб система функціонувала надійно в реальних школах, ліцеях та університетах, необхідно реалізувати 4 обов'язкові інженерні механізми:

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                   4 СТОВПИ ПРОДАКШЕН-ГОТОВНОСТІ КУРСОВОГО ДВИЖКА                 │
├──────────────────────────┬──────────────────────────┬────────────────────────────┤
│ 1. Версіонування Курсів  │ 2. Pre-Flight Linter     │ 3. Клонування та Форкінг   │
│    (Semantic Versioning) │    (100-бальний аудит)   │    (Course Forking)        │
├──────────────────────────┴──────────────────────────┴────────────────────────────┤
│ 4. Контентна Телеметрія та Автокалібрування BKT (Author Analytics Engine)       │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 6.1. Семантичне Версіонування Курсів (Course Versioning)
- **Проблема:** Якщо вчитель додає новий модуль або виправляє помилку в завданні під час навчального семестру, у студентів не повинен збиватися прогрес $P(L_n)$.
- **Рішення:**
  - Кожен курс має номер версії (`version: "1.0.0"`).
  - Створення курсу починається з версії `1.0.0-draft`.
  - Після публікації курс фіксується як `1.0.0`.
  - Подальші редагування відкривають **робочу чернеткову копію (Draft Fork)** наступної мінорної версії (`1.1.0-draft`).
  - Класи, які вже навчаються, спокійно закінчують курс на закріпленій версії `1.0.0`, а нові класи підключаються до `1.1.0`.

### 6.2. Автоматичний Інспектор Готовності (Pre-Flight Quality Linter)
Перед натисканням кнопки «🚀 Опублікувати курс» система запускає строгий автоматичний аудит якості та виставляє оцінку готовності від 0 до 100%:
- ❌ **Блокуючі помилки (Критичні):**
  - Виявлено циклічну залежність у графі компетенцій ($S_1 \to S_2 \to S_1$).
  - Модуль містить 0 компетенцій.
  - Компетенція містить 0 завдань (студент не зможе просунутися по BKT).
  - У кодової задачі немає валідаційних тестів.
- ⚠️ **Попередження (Неблокуючі):**
  - Модуль не має теоретичного опису для підручника (рекомендується додати).
  - У навички менше 3 завдань (рекомендується 3–5 задач для точного калібрування BKT).
  - Відсутні картки оман (Misconceptions) у теоретичному конспекті.

### 6.3. Клонування та Форкінг Курсів (Course Forking & Templating)
- Викладач може взяти будь-який базовий курс платформи (наприклад, «JavaScript & Web Engineering») і натиснути **`[ 🍴 Форкнути курс ]`**.
- Створюється повна незалежна копія у статусі чернетки, де викладач може:
  - Спростити або ускладнити пороги BKT під свій клас;
  - Додати власні практичні задачі;
  - Видалити зайві модулі.

### 6.4. Контентна Телеметрія та Автокалібрування BKT (Author Analytics)
Після проходження курсу учнями автор бачить аналітику контенту:
- **Індекс ковзання задачі $P(S)$:** Якщо 90% відмінників помиляються на конкретному питанні — в умові задачі є двозначність.
- **Індекс вгадування $P(G)$:** Якщо слабкі учні без спроб пишуть правильну відповідь — тест занадто очевидний.
- **Час читання конспекту:** Чи читають учні блок теорії перед переходом до практики.
