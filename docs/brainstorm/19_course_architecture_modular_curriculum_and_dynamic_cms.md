# 🧠 Сесія 19: Архітектура Налаштування Курсів, Модульна Дидактика, Пороги Майстерності BKT та Динамічний CMS

Цей документ фіксує результати 19-ї сесії архітектурного брейншторму платформи **Smart-BKT-Chain**, присвяченої комплексному налаштуванню навчальних курсів, ієрархічній структурі модулів, гнучким дидактичним режимам відкриття рівнів та селективному призначенню модулів викладачем.

## 🎯 1. Концепція та Дидактична Місія

Платформа Smart-BKT-Chain спроєктована як універсальне адаптивне середовище для учнів 10–11 класів, студентів коледжів та слухачів комп'ютерних академій. Для успішного впровадження у різноманітні навчальні плани потрібна не статична послідовність задач, а **гнучкий конструктор навчальних курсів та модулів**:

1. **Ієрархія Дидактичних Одиниць:**
   $$\text{Курс (Course)} \longrightarrow \text{Модулі (Modules)} \longrightarrow \text{Компетенції (Skill DAG Nodes)} \longrightarrow \text{Завдання & Теорія (Tasks & Units)}$$
2. **Дидактичні Режими Проходження (Enrollment Modes):**
   - **STANDARD (Повний адаптивний):** Послідовне проходження. Модуль 1 відкритий; ознайомлення з теорією відкриває адаптивний тренажер; досягнення порогу майстерності $P(L_n) \ge P_{\text{target}}$ автоматично відкриває Модуль 2 і наступні рівні.
   - **TESTING_ONLY (Діагностичний скринінг):** Миттєвий доступ до завдань без обов'язкового читання конспекту — для вхідного тестування, модульних контрольних або олімпіадних зрізів.
   - **THEORY_ONLY (Лекційний підручник):** Вільне вивчення теоретичних матеріалів, інтерактивних пісочниць та аналізу поширених помилок (Misconceptions).
3. **Селективне Підключення Модулів (Selective Modular Enrollment):**
   - Викладач може підключити для класу чи конкретного учня як **весь курс цілком**, так і **обрані модулі** (наприклад, активувати виключно «Модуль 3: Масиви та Об'єкти» для поточної теми семінару, заблокувавши інші).
4. **Централізований CMS в Адмінці:**
   - Повноцінне створення та редагування курсів, керування модулями, прив'язка посилань на теорію (`theoryUrl` підручника `apps/study`), конфігурація цільових порогів BKT ($P(L_n) \ge 0.85$).

## 📐 2. Математична Модель Відкриття Рівнів та BKT-Гейтинг (Mastery Gating)

### 2.1. Формула Оцінки Готовності до Наступного Модуля
Нехай курс $C$ складається з послідовності модулів $M_1, M_2, \dots, M_k$, де кожен модуль $M_i$ містить множину навичок $\{S_{i,1}, S_{i,2}, \dots, S_{i,m}\}$.
Для кожної навички $S$ поточна ймовірність засвоєння обчислюється класичним байєсівським оновленням знань:

$$P(L_n | \text{Correct}) = \frac{P(L_{n-1}) \cdot (1 - P(S))}{P(L_{n-1}) \cdot (1 - P(S)) + (1 - P(L_{n-1})) \cdot P(G)}$$

$$P(L_n | \text{Incorrect}) = \frac{P(L_{n-1}) \cdot P(S)}{P(L_{n-1}) \cdot P(S) + (1 - P(L_{n-1})) \cdot (1 - P(G))}$$

$$P(L_{n+1}) = P(L_n) + (1 - P(L_n)) \cdot P(T)$$

### 2.2. Умова Розблокування Модуля $M_{i+1}$ (Module Unlock Condition)
У режимі **STANDARD**:
1. Модуль $M_1$ завжди розблокований за замовчуванням.
2. Модуль $M_{i+1}$ стає доступним студенту тоді й тільки тоді, коли:
   $$\forall S \in M_i^{\text{required}}: \quad P(L_n^{(S)}) \ge P_{\text{target}} \quad (\text{де за замовчуванням } P_{\text{target}} = 0.85)$$
   або середній рівень опанування навичок модуля перевищує поріг:
   $$\bar{P}(L^{(M_i)}) = \frac{1}{|M_i|} \sum_{S \in M_i} P(L_n^{(S)}) \ge P_{\text{target}}$$
3. У режимі **TESTING_ONLY**:
   $$\text{isUnlocked}(M_i) = \text{true} \quad \forall M_i \in \text{allowedModules}$$
   Усі призначені модулі доступні одночасно для швидкої діагностики знань.

## 🗄️ 3. Еволюція Схеми Бази Даних (Prisma Database Schema)

### 3.1. Нова Модель: `CourseModule`
Для забезпечення суворої ієрархії додається таблиця `course_modules`:

```prisma
model CourseModule {
  id                    String      @id @default(uuid())
  courseId              String
  course                Course      @relation(fields: [courseId], references: [id], onDelete: Cascade)
  slug                  String
  title                 String      // напр. "Модуль 1: Синтаксис & Змінні"
  description           String?
  orderIndex            Int         @default(0)
  theoryUrl             String?     // посилання на підручник: "/learn/js-dev/module-1"
  minMasteryThreshold   Float       @default(0.85) // поріг відкриття наступного модуля
  createdAt             DateTime    @default(now())
  updatedAt             DateTime    @updatedAt
  skills                SkillNode[]

  @@unique([courseId, slug])
  @@index([courseId, orderIndex])
  @@map("course_modules")
}
```

### 3.2. Розширення Моделей `Course`, `SkillNode`, `Classroom`, `CourseEnrollment`
- **`Course`:**
  - `modules CourseModule[]` — зв'язок один-до-багатьох із модулями.
  - `isPublished Boolean @default(true)` — видимість у каталозі.
  - `targetAudience String?` — рівень («10–11 класи», «Спеціальність 122/014», тощо).
  - `defaultMasteryThreshold Float @default(0.85)` — дефолтний поріг BKT.
- **`SkillNode`:**
  - `moduleId String?` — зовнішній ключ до `CourseModule`.
  - `module CourseModule? @relation(...)`
  - `orderIndex Int @default(0)` — порядок у межах модуля.
- **`Classroom` та `CourseEnrollment`:**
  - `allowedModuleIds Json?` — масив ID дозволених модулів (`null` = усі модулі доступні).

## 🌐 4. Специфікація REST API

| Метод | Ендпоінт | Призначення | Авторизація |
|---|---|---|---|
| `GET` | `/api/v1/courses` | Отримати перелік курсів з модулями та кількістю навичок | Публічний / JWT |
| `GET` | `/api/v1/courses/:slug` | Отримати повну структуру курсу (модулі, навички DAG, задачі) | Публічний / JWT |
| `POST` | `/api/v1/courses` | Створити новий навчальний курс | Admin |
| `PATCH` | `/api/v1/courses/:id` | Оновити параметри курсу (назва, опис, поріг BKT, статус) | Admin |
| `DELETE` | `/api/v1/courses/:id` | Видалити курс (з валідацією активних студентів) | Admin |
| `POST` | `/api/v1/courses/:courseId/modules` | Створити новий модуль у курсі | Admin |
| `PATCH` | `/api/v1/courses/:courseId/modules/:moduleId` | Оновити модуль (назва, порядок, теорія, поріг) | Admin |
| `DELETE` | `/api/v1/courses/:courseId/modules/:moduleId` | Видалити модуль | Admin |
| `POST` | `/api/v1/classrooms` | Створити клас із підтримкою `allowedModuleIds` | Teacher / Admin |
| `PATCH` | `/api/v1/classrooms/:id` | Змінити налаштування класу або перелік дозволених модулів | Teacher / Admin |

## 🖥️ 5. Дизайн Інтерфейсів та UX Архітектура

### 5.1. Admin Portal (`apps/admin`) — Панель Управління Курсами та Модулями
- **Каталог курсів:**
  - Табличний/картковий огляд із бейджами кількості модулів, компетенцій та цільового порогу $P(L_n)$.
  - Кнопка швидкого створення `[+ Створити курс]`.
- **Редактор курсу та модулів:**
  - Модальне вікно або вбудована панель редагування метаданих курсу.
  - Список модулів із можливістю впорядкування (`orderIndex`), зміни назви, опису та посилання на підручник `apps/study`.
  - Можливість призначення навичок (Skill Nodes) до модулів.

### 5.2. Teacher Portal (`apps/teacher`) — Гнучкий Селектор Модулів у Класах
- **Створення навчальної групи (`CreateClassroomModal`):**
  - При виборі курсу з'являється блок вибору модулів:
    - `[x] Дозволити весь курс (рекомендовано)`
    - `[ ] Вибрати окремі модулі вручну`
  - Якщо обрано ручний вибір — з'являється список чекбоксів із назвами модулів.
- **Картка класу:**
  - Показує бейдж: `Усі модулі` або `3 модулі активні`.

### 5.3. Student Portal (`apps/student`) — Модульний Сайдбар та Гейтинг
- **Сайдбар компетенцій:**
  - Навички групуються за модулями (`DrawerSection` для кожного модуля).
  - Стан модуля:
    - 🟢 `Розблоковано` (відкритий для розв'язання);
    - 🔒 `Заблоковано` (необхідно завершити попередній модуль або відкрити теорію);
    - 🏁 `Засвоєно` ($P(L_n) \ge 0.85$).
- **Перемикач курсів:**
  - Уніфікований `UserProfileDrawer` дозволяє перемикати активний курс, показуючи індивідуальний прогрес.
