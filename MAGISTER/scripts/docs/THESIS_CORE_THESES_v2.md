## 🧩 БЛОК 3. «Скляна стеля» чистого BKT та наше інженерно-математичне подолання

У чистому BKT (Corbett & Anderson, 1994) виявлено 4 критичні математичні та поведінкові проблеми:

```
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                           ПРОБЛЕМИ ЧИСТОГО BKT («СКЛЯНА СТЕЛЯ»)                             │
├───────────────────────────────┬───────────────────────────────┬─────────────────────────────┤
│ 1. Lucky Guess Spike          │ 2. Zero-Learning Sink         │ 3. The Frustration Loop     │
│    (Випадкове вгадування)     │    (Математична прірва нуля)  │    (Адаптивний тупик)       │
├───────────────────────────────┼───────────────────────────────┼─────────────────────────────┤
│ Студент випадково вгадав або  │ Серія помилок опускає P(L)    │ BKT знижує рівень, але не   │
│ вставив код за 2 сек. Чистий  │ до 0.00001. Потрібно 25 іде-  │ пояснює суть помилки. Сту-  │
│ BKT різко піднімає P(L) -> 1. │ альних відповідей для виходу. │ дент застрягає в циклі.     │
└───────────────────────────────┴───────────────────────────────┴─────────────────────────────┘
                                                │
                                                ▼
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                                НАШЕ ІНЖЕНЕРНЕ ПОДОЛАННЯ                                     │
├───────────────────────────────┬───────────────────────────────┬─────────────────────────────┤
│ 1. Динамічний P(G_t)          │ 2. Нижня асимптота Clamping   │ 3. DAG Backtracking +       │
│    Штраф за спідран (<4 с)    │    P(L) in [0.05, 0.999]      │    Scaffolding (Підказки,   │
│    та вставку PasteRatio>0.7  │    Гарантія реабілітації      │    картки оман, Cool-down)  │
└───────────────────────────────┴───────────────────────────────┴─────────────────────────────┘
```

### 1. Лістинг реалізації математичного ядра BktEngine з Clamping:
```typescript
// apps/api/src/domain/bkt/bkt.engine.ts
export class BktEngine {
  private static readonly P_MIN = 0.05;  // Нижня асимптота (подолання прірви)
  private static readonly P_MAX = 0.999; // Захист від сингулярності ділення

  public static calculateNextState(
    prevL: number,
    isCorrect: boolean,
    pSlip: number,
    pGuess: number,
    pTransit: number
  ): number {
    // Байєсівське оновлення апостеріорної ймовірності
    let pObserved: number;
    if (isCorrect) {
      pObserved = (prevL * (1 - pSlip)) / (prevL * (1 - pSlip) + (1 - prevL) * pGuess);
    } else {
      pObserved = (prevL * pSlip) / (prevL * pSlip + (1 - prevL) * (1 - pGuess));
    }

    // Врахування переходу знання (ефект навчання)
    const nextL = pObserved + (1 - pObserved) * pTransit;

    // Застосування правила числових границь Clamping
    return Math.min(Math.max(nextL, this.P_MIN), this.P_MAX);
  }
}
```

### 2. Лістинг динамічного регулятора BehavioralAdjuster:
```typescript
// apps/api/src/domain/bkt/behavioral.adjuster.ts
export class BehavioralAdjuster {
  public static adjust(telemetry: TelemetryPayload, baseGuess = 0.2, baseSlip = 0.1) {
    let pGuess = baseGuess;
    let pSlip = baseSlip;

    // Детекція швидкого вгадування / вставки стороннього розв'язку
    if (telemetry.timeToSolveMs < 4000 || telemetry.pasteRatio > 0.70) {
      pGuess = 0.85; // Штрафуємо випадковий або списаний успіх
    }

    // Врахування глибокого рефакторингу (захист від штрафу за описку)
    if (telemetry.timeToSolveMs > 60000 && telemetry.backspaceCount > 20) {
      pSlip = 0.35; // Дозволяємо помилку неуважності досвідченому учню
    }

    return { pGuess, pSlip };
  }
}
```

## 🏛️ БЛОК 4. Архітектура та структура повноцінної EdTech-системи

У магістерській роботі детально описується модульна структура монорепозиторію, де кожен застосунок вирішує замкнену дидактичну чи управлінську задачу:

```text
smart-bkt-chain/
├── apps/
│   ├── study/        # Порт 3006: Дидактичний портал (Zen Focus, Misconceptions, Playground)
│   ├── student/      # Порт 3002: Тренажер (Monaco Editor, Skill DAG Map, Live Telemetry)
│   ├── teacher/      # Порт 3003: Моніторинг (BKT Heatmap, Review Queue Inspector, Anomaly Radar)
│   ├── admin/        # Порт 3004: CMS Методиста (Skill DAG Visual Builder, Course Manager)
│   └── api/          # Порт 3000: Гексагональний NestJS Core (WebSockets, BktEngine, BullMQ)
├── packages/
│   ├── database/     # Prisma ORM, PostgreSQL schema, міграції
│   ├── types/        # Спільні TypeScript DTO контракти
│   └── ui/           # Спільна бібліотека компонентів (@sbc/ui, DrawerSection)
└── contracts/        # Solidity смарт-контракти (SoulboundCertificate.sol)
```

### Рольові характеристики застосунків:
1. **`apps/study` (Навчальний портал, 3006):**
   - *Призначення:* Первинне сприйняття теорії без стресу екзаменації.
   - *Компоненти:* `ReaderFloatingToolbar` (Zen Focus), `MisconceptionCard` (розбір ментальних оман), `CodePlayground` (пісочниця живого виконання коду).
2. **`apps/student` (Тренажер учня, 3002):**
   - *Призначення:* Практичне закріплення через написання коду.
   - *Компоненти:* `MonacoCodeEditor` з хуком `useBehavioralTelemetry`, `SkillDagMap` (інтерактивне візуальне дерево знань), бічна панель за стандартом Rule 7.
3. **`apps/teacher` (Кабінет викладача, 3003):**
   - *Призначення:* Педагогічний аналіз когорт та валідація аномалій.
   - *Компоненти:* `BktHeatmapGrid`, `AnomalyRadarWidget`, `ReviewQueueInspector` (черга перевірки з дедуплікацією спроб `SUPERSEDED` / `APPROVED`).
4. **`apps/admin` (Методичний центр, 3004):**
   - *Призначення:* Конструювання графів навичок та налаштування BKT матриць.
   - *Компоненти:* `SkillDagBuilder` (drag-and-drop редактор орієнтованих графів), `CourseCmsManager`.
5. **`apps/api` (Бекенд-ядро, 3000):**
   - *Призначення:* Обробка високочастотної телеметрії, розрахунки BKT та трансляція подій.
   - *Компоненти:* `TelemetryGateway` (Socket.IO шлюз), `BktEngine`, `TaskSequencer`, `PrismaService`.

## 🧪 БЛОК 5. Експериментальні дослідження та підтвердження ефективності

### 1. Зниження похибки та зростання дискримінаційної здатності:
На тестовій вибірці з 1200 сесій алгоритмічного кодописання:
- **$RMSE$:** знизився з $0.382$ (Standard BKT) до **$0.214$** (Telemetry BKT) — покращення точності прогнозу на **$44.0\%$**!
- **$AUC-ROC$:** зріс з $0.748$ до **$0.871$** (система значно чіткіше розрізняє реальне знання та здогад).

### 2. Стійкість до генеративного ШІ та буфера обміну (Копіювання коду):
- Змодельовано $200$ аномальних спроб із миттєвою вставкою безпомилкового коду з буфера обміну ($R_{paste} > 0.85$, $t < 3$ с).
- **Результат у чистому BKT:** 100% спроб призвели до переходу в стан «Опановано» ($P(L) > 0.95$, хибнопозитивна сертифікація).
- **Результат у Smart-BKT-Chain:** 74% спроб були своєчасно пеналізовані динамічним регулятором $P(G) \rightarrow 0.85$, статус майстерності заблоковано, середній коефіцієнт довіри знизився до $\bar{C}_{trust} = 0.22$, а спробу передано в `ReviewQueueInspector` викладача.
