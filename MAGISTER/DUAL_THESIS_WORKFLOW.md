## 🗂️ 2. Структура Каталогів та Ізоляція Даних

Щоб результати першої роботи залишалися на 100% незмінними при розробці другої, файлова система структурована так:

```text
MAGISTER/
├── THESIS_RULES.md                  <-- 📜 Звід правил етики, стилю та ДСТУ (спільний)
├── DUAL_THESIS_WORKFLOW.md          <-- 🧭 Цей документ: інструкція з перемикання
│
├── KN/                              <-- 🛡️ РОБОТА №1 (122 Комп'ютерні науки)
│   ├── sections/                    <-- 🔒 Ізольовані розділи роботи 122 (intro, sec 1..5)
│   ├── generate_full_text.py        <-- Збирач дерева для 122
│   ├── thesis_spec.json             <-- Специфікація та повне дерево тексту 122
│   ├── Магістерська_робота_122.docx <-- Згенерований фінальний документ (55+ стор.)
│   └── README.md
│
├── INFORMATICA/                     <-- 🎓 РОБОТА №2 (014 Середня освіта)
│   ├── sections/                    <-- 🔒 Ізольовані методичні розділи 014
│   ├── generate_full_text.py        <-- Збирач дерева для 014
│   ├── thesis_spec.json             <-- Специфікація методичного дослідження
│   ├── Магістерська_робота_014.docx <-- Згенерований документ під методику
│   └── README.md                    <-- Педагогічна концепція та граф шкільних навичок
│
└── scripts/                         <-- ⚙️ СПІЛЬНИЙ КОНВЕЄР ГЕНЕРАЦІЇ
    ├── thesis_profile.py            <-- Диспетчер шляхів та профілів (kn, info)
    ├── generate_docx.py             <-- Універсальний рушій ДСТУ-верстки Word
    ├── build_full_spec.py           <-- Головний CLI-складальник специфікацій (--profile kn|info)
    └── build_full_spec_info.py      <-- Профільний модуль специфікації для 014
```

## 🔄 3. Механізм Безпечного Перемикання Між Роботами

### Принцип ізоляції контенту:
1. **Незмінність Роботи №1:**  
   Всі напрацьовані розділи, формули BKT, схеми архітектури, таблиці та згенерований файл `Магістерська_робота_122.docx` зафіксовані в Git-гілці та захищені від випадкового перезапису.
2. **Параметризований запуск генератора:**  
   Спільний скрипт верстки `generate_docx.py` приймає прапорець профілю (або шлях до специфікації):
   - Для комп'ютерних наук (122):
     ```powershell
     python MAGISTER/scripts/generate_docx.py --profile kn
     ```
   - Для середньої освіти (014):
     ```powershell
     python MAGISTER/scripts/generate_docx.py --profile info
     ```
3. **Спільні правила — окремий зміст:**  
   Обидва конвеєри використовують єдиний файл правил [`MAGISTER/THESIS_RULES.md`](file:///d:/PROJECTS/MAGISTERS/SMART-BKT-CHAIN/MAGISTER/THESIS_RULES.md) та Правило 9 регламенту [`.agents/AGENTS.md`](file:///d:/PROJECTS/MAGISTERS/SMART-BKT-CHAIN/.agents/AGENTS.md).
