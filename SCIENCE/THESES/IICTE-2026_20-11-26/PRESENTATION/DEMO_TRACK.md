# 🎬 Трек живої демонстрації платформи Smart-BKT-Chain (IICTE-2026)

Цей документ є покроковим режисерським сценарієм **4–4.5-хвилинної живої демонстрації** платформи **Smart-BKT-Chain** у межах доповіді **«Динамічна персоналізація освітніх траєкторій в інтелектуальних навчальних системах»** на конференції **IICTE-2026** (Секція 1 «Штучний інтелект в освіті», регламент 12–15 хв).

Кожен крок демонстрації жорстко прив'язаний до математичного апарату поданих тез (`V-4.0`, формули `(1)`–`(7)`, Таблиця 1) та реальної поведінки кодової бази (`BehavioralAdjuster`, `bkt.controller.ts`, `GameSkillTreeWidget`, `ReviewQueueInspector`, `MetricsAuditInspector`).

## ⚙️ 0. Передстартовий чек-лист (за 15 хвилин до виступу)

1. **Запуск сервісів:**
   - Бекенд API: `http://localhost:3000` (`apps/api`)
   - Кабінет студента: `http://localhost:3002` (`apps/student`)
   - Кабінет викладача: `http://localhost:3003` (`apps/teacher`)
   - Адмін / Методичний центр: `http://localhost:3004` (`apps/admin`)
   - Інтерактивний підручник *(опційно для Q&A)*: `http://localhost:3006` (`apps/study`)
2. **Налаштування відображення (для Zoom / Meet / проєктора):**
   - Увімкнути **Світлу тему (Light Theme)** через `UserProfileDrawer` → `ThemeToggle` (найвища читабельність у трансляції).
   - Масштаб браузера: `110%` (щоб формули, бейджі `P(L)` та код у Monaco Editor чітко читалися на будь-якому екрані).
3. **Автентифікація та чистий стан:**
   - Переконатися, що `SYSTEM_AUTH_TEST_MODE = true` (вхід в 1 клік як `demo-student` та `teacher-olena` без затримок Google OAuth).
   - У `apps/student` → `UserProfileDrawer` → натиснути **«Скинути прогрес BKT»** для чистого старту демонстрації.
   - Обрати активний курс: **«Вебтехнології та алгоритмізація (10–11 класи)»** (`web-algorithms-school`).
4. **Заготовлені фрагменти (тримати поруч у блокноті для швидкого копіювання):**
   - *Хибний код із когнітивною оманою (Акт 3):*
     ```javascript
     function convertToUsd(uahAmount, exchangeRate) {
       return uahAmount * exchangeRate;
     }
     ```
   - *Правильний код (Акт 3 — вводити вручну у природному темпі):*
     ```javascript
     function convertToUsd(uahAmount, exchangeRate) {
       return Number((uahAmount / exchangeRate).toFixed(2));
     }
     ```
5. **План «Б»:** заздалегідь записаний 3-хвилинний резервний скрінкаст цього ж маршруту (на випадок перебоїв зв'язку чи локального сервера).

## 🎭 Покроковий сценарій виступу

### Акт 1. Структура курсу як граф пререквізитів Skill DAG (`0:00–0:40`)
- **Екран:** `http://localhost:3002` (`apps/student`), вкладка на лівій рейці **Дерево компетенцій (`tree`)** або **Граф BKT (`bkt`)**.
- **Дія:** Показати курсором кореневі вузли модуля 1 (*«Змінні та типи даних»*, *«Лінійні обчислення»*) і заблоковані дочірні вузли (*«Умовні розгалуження»*, *«Цикли»*).
- **Репліка доповідача:**
  > *«Перейдемо до живої демонстрації платформи Smart-BKT-Chain на прикладі шкільного курсу інформатики для 10–11 класів. Перед вами орієнтований ациклічний граф знань Skill DAG — формула (5) наших тез. Доступ до наступної теми відкривається лише тоді, коли для всіх її пререквізитів байєсівська оцінка володіння досягає порогу $\tau_{\text{mastery}} = 0{,}85$.»*

---

### Акт 2. Детекція поведінкових аномалій та динамічне $P_{\text{adj}}(G)$ (`0:40–1:40`)
- **Екран:** Перемикаємось на вкладку **Завдання (`task`)**.
- **Сцена 2А — Надшвидке вгадування (`SINGLE_CHOICE`):**
  - Завдання: *«Теорія: Оголошення змінних `let` та `const`»*.
  - **Дія:** Одразу (менш ніж за **3 секунди**) клікаємо правильний варіант **`const`** і тиснемо **«Перевірити»**.
  - **Що бачить аудиторія:** Відповідь формально правильна ($Y_n = 1$), **але** `BehavioralAdjuster` фіксує латентність `< 3500 мс`, піднімає параметр вгадування до $P_{\text{adj}}(G) = 0{,}85$ і виводить попередження `⚡ (Високий показник латентності: можливе вгадування)`. Приріст $P(L_n)$ мінімальний — тема не зараховується.
- **Сцена 2Б — Копіпаст у відкритій відповіді / коді *(залежно від активного завдання)*:**
  - Якщо відкрито завдання `TEXT_ESSAY` / `OPEN_TEXT`: вставляємо підготовлену відповідь через `Ctrl+V` → `BehavioralAdjuster` піднімає $P_{\text{adj}}(G) = 0{,}90$, а контролер **автоматично спрямовує роботу в чергу викладача (`PENDING_REVIEW`)** з позначкою аномалії.
  - Якщо відкрито `CODE` у Monaco Editor: вставка `Ctrl+V` миттєво фіксується WebSocket-телеметрією у `BehaviorProfile` (`copyPasteRatio = 100%`) і підсвічується на радарі викладача.
- **Репліка доповідача:**
  > *«Зверніть увагу: відповідь формально правильна, проте система зафіксувала аномально малий час реакції. Згідно з формулами (6)–(7), індекс довіри знизився, параметр вгадування $P_{\text{adj}}(G)$ зріс, і знаменник формули Баєса заблокував фіктивний приріст знань. Таким чином модель захищена від механічного проклікування та сліпого копіювання.»*

---

### Акт 3. Діагностика омани, Сократівські підказки та чесне опанування (`1:40–2:40`)
- **Екран:** Практичне завдання з коду (`CODE`) — *«Практика (Ремедіація): Лінійний конвертер гривень у долари»* (`convertToUsd`).
- **Дія 1 (Типова помилка):** Вводимо типову учнівську помилку `return uahAmount * exchangeRate;` і запускаємо перевірку.
- **Що бачить аудиторія:**
  1. Система не просто пише «Wrong Answer», а діагностує конкретну **когнітивну оману** (*«Множення замість ділення при конвертації гривень у долари»*).
  2. У сайдбарі розкриваємо **Сократівські підказки** (рівні 1–2) — ШІ дає навідне питання без готового коду (із демпфуванням приросту).
  3. За протоколом прогресивної ескалації **розблоковується шторка експрес-теорії (`JustInTimeTheoryDrawer`)**, яка раніше була під замком 🔒, щоб уникнути «арбітражу допомоги».
- **Дія 2 (Самостійне виправлення):** Вручну у природному темпі (з короткою паузою ~2–3 сек) дописуємо правильний рядок:
  `return Number((uahAmount / exchangeRate).toFixed(2));` і тиснемо **«Перевірити»**.
- **Що бачить аудиторія:** Усі автотести (включно з прихованим) проходять, телеметрія підтверджує самостійність, $P(L_n)$ зростає, навичка переходить у стан **Mastered** ($\ge 0{,}85$), а граф Skill DAG розблоковує наступний концепт.
- **Репліка доповідача:**
  > *«Тепер поглянемо на дидактичну роль ШІ. Коли учень припускається типової помилки, система ідентифікує когнітивну оману, пропонує ступеневу Сократівську підказку та розблоковує концентровану експрес-теорію прямо в редакторі. Після самостійного виправлення байєсівська оцінка перетинає поріг 0,85, і траєкторія динамічно відкриває наступний вузол графа.»*

---

### Акт 4. Кабінет викладача — Пояснюваний ШІ (XAI) та Human-in-the-Loop (`2:40–3:45`)
- **Екран:** Клікаємо внизу лівої рейки іконку **Кабінет викладача** → миттєвий перехід на `http://localhost:3003` (`apps/teacher`).
- **Дія 1 (`analytics`):** За 10 секунд показуємо когортний розподіл майстерності та **радар ризиків** (де відображається аномальна телеметрія студента).
- **Дія 2 (`reviews` — `ReviewQueueInspector`):** Відкриваємо вкладку **Черга перевірки** (із числовим бейджем). Показуємо зафіксовану аномальну спробу, її телеметрію та кнопки педагогічного рішення **`APPROVE` / `REJECT`**.
- **Дія 3 (`metrics-audit` — `MetricsAuditInspector`):** *(Ключовий вау-момент для наукової аудиторії!)* Відкриваємо **What-If BKT Sandbox** і наживо рухаємо повзунок $P(G)$ від `0.15` до `0.90`, демонструючи, як прозоро й миттєво змінюється апостеріорна ймовірність $P(L_n)$.
- **Репліка доповідача:**
  > *«На відміну від нейромережевих "чорних скриньок", викладач у нашій системі бачить повну пояснюваність кожного рішення. У черзі перевірки фіксуються роботи з аномальною телеметрією, де фінальне слово залишається за педагогом — принцип Human-in-the-Loop. А вбудований симулятор дозволяє наочно перевірити роботу байєсівського ядра за будь-яких параметрів.»*

### Акт 5. Опційний козир / Під час запитань (Q&A) (`3:45–4:10`)
Тримаємо відкритими два потужні аргументи на випадок запитань комісії:
1. **«Як ви перевірили коректність математичних формул у коді?»**

2. **«Чи складно викладачу створювати курси під такий граф?»**
   → `apps/admin` (`3004`) → вкладка **`courses`** → показуємо кнопки **«✨ ШІ-Генератор»** (AI Course Scaffolder) та **«Імпорт (.xlsx)»** (5-вкладковий Excel-шаблон).
3. **«Де учні читають теорію перед практикою?»**
   → `apps/study` (`3006`) → показуємо інтерактивний підручник із **Zen-режимом читання** (клавіша `Z`) та вбудованою пісочницею `CodePlayground`.

## 💬 Шпаргалка відповідей на типові запитання комісії (Q&A)

1. **Про цифри експерименту (Таблиця 1 поданих тез `V-4.0`):**
   - Вибірка: $M = 500$ синтетичних агентів, граф із $m = 15$ навичок, $P(L_0) = 0{,}15, P(T) = 0{,}20, P(G) = 0{,}15, P(S) = 0{,}10$.
   - Середня кількість завдань до опанування: `19,3 → 14,2` (**−26,4%**).
   - Частка нескомпенсованих навчальних труднощів: `18,6% → 11,5%` (**−38,1%**).
   - Індекс збереження пізнавальної залученості ($K_{\text{err}} < 3$): `0,62 → 0,84` (**+35,5%**).
   - *Важливо:* чесно підкреслюємо, що це результати імітаційного моделювання Монте-Карло, а розгорнутий педагогічний експеримент у коледжі/школі є наступним етапом дослідження.
2. **Про приватність телеметрії:**
   - Жодної біометрії, вебкамери, запису екрана чи кейлогера поза браузером — аналізуються лише знеособлені події редактора (інтервали пауз, WPM, кількість вставок/видалень) у межах конкретної навчальної задачі.
3. **Чому BKT, а не Deep Knowledge Tracing (DKT)?**
   - DKT потребує десятків тисяч взаємодій для навчання та працює як «чорна скринька». BKT забезпечує **холодний старт** для нового курсу та повну **інтерпретованість (XAI)** кожного кроку для вчителя й учня.
